# 2026.215.1549 — Clear three high-severity advisories

`npm audit` reported three high-severity advisories in this repo's dependency tree. All three
resolve to one non-major bump: `wrangler` `4.110.0` → `4.118.0`.

| Advisory | Path |
|---|---|
| `wrangler` | direct devDependency |
| `miniflare` | via `wrangler` |
| `sharp` — libvips CVE-2026-33327 / -33328 / -35590 / -35591 (GHSA-f88m-g3jw-g9cj) | via `wrangler` → `miniflare` |

## Owning where they came from

All three have **one** origin: the `wrangler` devDependency this cutover pinned (so
`wrangler-action` stops installing it outside the lockfile at deploy time). The vulnerable
`sharp` is `node_modules/miniflare/node_modules/sharp`, reachable only through
`wrangler` → `miniflare`.

An earlier draft of this entry said `sharp` "was installed alongside Astro in the same cutover",
implying two independent origins. That is wrong, and its own table contradicted it. Measured: the
Astro-installed direct `sharp` is `^0.35.3` on both base and head, untouched by this change,
outside the advisory's `<0.35.0` range, and absent from the audit tree — the only line
`package.json` moves here is `wrangler`.

The correction does not change the conclusion, only its shape: the advisories arrived with work
landed hours earlier in this same chain, so they are cleared here rather than deferred.

## Verified

`npm audit` reports **zero** vulnerabilities at any severity. From a removed `node_modules`:
`npm ci` exits 0, `npx --no-install wrangler --version` resolves `4.118.0` from the lockfile —
preserving the property that the deploy action installs nothing and no deployment is stamped
`commit_dirty` — and `npm run build` produces 840 routes.

`npm audit fix` alone does not resolve these; it leaves all three in place because the fix is a
minor bump outside the committed range. The pin was moved deliberately instead.
