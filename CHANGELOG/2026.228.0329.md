# 2026.228.0329 — two correct measurements diverged because the unit was unstated

A footnote to `2026.228.0249`, which swept the claims `sdk#138` falsified. That
entry's control read:

> the looser `useradd -m -u` reads **5 → 4**

Reviewing it, a validator measured **6** where the author measured **5**.
Neither was wrong.

```
pre-sweep  69f97926   5 files / 6 hits
post-sweep 438bfda5   4 files / 4 hits
```

`recipes/distros/debian.md` carries the pattern twice — once in prose at line 39
without `-s /bin/bash`, once in a code block at line 55 with it. That asymmetry
is the whole explanation: the **strict** pattern (`useradd -m .* -s /bin/bash`,
the one that actually measures the defect) counts 4, while the **loose** pattern
counts 6 hits across 5 files.

`5 → 4` was true as a file count. Nothing in that entry was wrong. What it never
said was **which unit it was counting** — so two people measured the same thing
correctly and disagreed.

## The rule this yields

**An unqualified count is the same ambiguity as an unqualified pattern.** The
`2026.228.0249` entry already argued that a control must state its pattern and
its scope, because a looser pattern silently counts a different population. The
unit is the third axis and it was missed while making exactly that argument.

State all three: pattern, scope, unit. A control that omits any of them can be
read two correct ways.

## Why this is a separate entry

The reconciliation was first written as an amendment to `2026.228.0249` itself.
That is not permitted: a merged `CHANGELOG/<CalVer>.md` is closed history, and
follow-up work never edits it *even to add a directly-related narrative*
(`/charly-internals:git-workflow`, `references/validator-and-calver.md`). Editing
it would have re-dated history under a filename↔tag pairing that already points
at `v2026.228.0249`.

The author's framing — that a *clarification* may amend where a *correction* may
not — is not a distinction the rule makes; both collapse to the same remedy. A
fresh validator caught it before it landed, which is the mechanism the rule names
for exactly this mistake.
