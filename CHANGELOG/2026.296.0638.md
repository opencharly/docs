# 2026.296.0638 — fix(docs): the corpus-currency report names the pin contract's states and judges only from a decidable history

Closes #171

## Summary

The corpus-currency report in this repo's generation workflow named a state the pin contract does not have, and it judged the pin from a history that cannot answer the question.

**The false state.** The report called a corpus pin that is off the corpus's merged main *"not an ancestor of the corpus's merged main — a divergence, not an advance"*. The corpus is squash-merged, so such a pin is a **squash-advance** — and the pin contract says the opposite: its remedy is the same as `behind`'s, and *"it is not a divergence"*. The report therefore told a reader that a healthy, merged, advanceable pin was a broken edge.

**The undecidable judgment.** The report judged the pin with `git merge-base --is-ancestor`, and the corpus checkout in CI is a **depth-1 clone**: `actions/checkout@v7` runs `git submodule update --init --force --depth=<fetch-depth>` (`src/git-command-manager.ts`, `submoduleUpdate`) with the default `fetch-depth: 1`. A depth-1 history answers *"not an ancestor"* for a commit it simply does not have — **indistinguishable from a real squash-advance**. Measured, in the CI shape: a depth-1 checkout pinned at a commit two behind the corpus's merged main reported a **divergence** for a pin that is merely behind. That is the same false state, produced by a second mechanism, and it is the one CI would have shown on every run.

**What this change does.**

- The report now names the **pin contract's own states** (umbrella `AGENTS.md` Part II rule 3): `cur`, `behind`, `not-on-the-served-line` — plus the two it refuses to guess, `undecidable` and `unreadable`. The vocabulary is the producer-side sibling's (`opencharly/marketplace` `scripts/consumer-currency.sh`), so both sides of the corpus contract speak one language.
- The report **deepens a shallow corpus before it judges**, and says `undecidable` when it cannot. A report that stated a state it could not establish would be worse than no report.
- The report's own header now states the two vantages honestly: the producer judges from the corpus's OWN history and refuses to judge a shallow one; this report judges from the consumer's checkout and deepens it first.
- The test builds **every state the report can name** as a fixture — including the CI shape (a depth-1 checkout at a behind pin) — and asserts the report never calls a squash-advance a divergence.

**What it does not do.** The corpus **pin** is not touched by this PR: the pinned corpus is 4 commits behind the corpus's merged main, and advancing it is a **pin-bump PR** with the regenerated pages — a separate cutover, in this repo, and the consumer leg of `opencharly/marketplace#543`. This change only makes the report *able to say so* (it already did say so on a full history, but CI never had one).
