# 2026.231.0052 — the ollama pages say what the candy declares, not what the image contains

Docs projection of the candy prose corrections in `charly#309`, the sibling of the
`plugins` projection in `plugins#210`.

Both ollama pages asserted that GPU support is composed outside the candy — one as
"never by this candy", the other as "GPU support is composed outside it" — on pages
that ALSO state a tarball distro receives one upstream archive already containing the
CUDA backend. A reader taking the first claim plainly and then reading the second had
no way to reconcile them, and the reading it invites (a plain tarball ollama image is
CPU-only) is false.

The corrected wording separates what the candy DECLARES (no GPU dependency — true on
every distro, and the reason the backend candies exist) from what an image CONTAINS
(packaged distros are genuinely CPU-only until a backend is composed; tarball distros
carry CUDA in the archive regardless).

The `ollama` page additionally stops pointing at a size "table" it does not have —
the figures are bullets — and states the backend rule that actually holds: both
backend candies package only on Arch, and off Arch they diverge, with `ollama-cuda`
degrading into an assertion that the tarball's bundled CUDA is present while
`ollama-rocm` has no tarball path at all.

An earlier revision of this branch went further and named which boxes compose which
backend. That was FALSE and this PR's validator caught it: at the gitlinks the source
branch pins — those repositories' `main` — neither distro submodule composes either
backend candy, and the composition exists only on the unmerged `feat/ollama-plugin`
branches of `distro-fedora#18` and `distro-cachyos#15`. The enumeration is deleted at
the candy source rather than corrected, because naming boxes on this page was itself
the defect: that list lives in the distro submodules, moves there, and any copy here
goes stale the moment one of those PRs lands.

Generated by `charly docs generate` (`task docs:sync`) from the corrected candy
sources; never hand-edited.

The size accounting on the `ollama` page is corrected in the same round, from
`plugins#210`'s cold reader: the two figures below the download line are the two
ALTERNATIVE backends, not the cost of a packaged build. A packaged image pays the 66 MiB
base plus at most one of them, and neither if it composes neither; and `~988 MiB` was
unscoped one paragraph before the page explains that off Arch `ollama-cuda` adds no
package at all.
