# 2026.231.0052 — the ollama pages say what the candy declares, not what the image contains

Docs projection of the candy prose corrections in `charly#309`, the sibling of the
`plugins` projection in `plugins#210`.

Both ollama pages asserted that GPU support is composed outside the candy — one as
"never by this candy", the other as "GPU support is composed outside it" — on pages
that ALSO state a tarball distro receives one upstream archive already containing the
CUDA backend. A reader taking the first claim plainly and then reading the second had
no way to reconcile them, and the reading it invites (a plain tarball ollama image is
CPU-only) is false.

The corrected wording separates what the candy DECLARES (no GPU dependency — true on
every distro, and the reason the backend candies exist) from what an image CONTAINS
(packaged distros are genuinely CPU-only until a backend is composed; tarball distros
carry CUDA in the archive regardless).

The `ollama` page additionally stops pointing at a size "table" it does not have —
the figures are bullets — and stops sending an AMD reader to `box/fedora`: both
backend candies package only on Arch, and off Arch they diverge, with `ollama-cuda`
degrading into an assertion that the tarball's bundled CUDA is present while
`ollama-rocm` has no tarball path at all.
