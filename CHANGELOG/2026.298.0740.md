# 2026.298.0740 — fix(ci): bound every job and step in this repo's workflows, and keep the bound enforced

## Summary

**Every step and every job in this repo's own deploy workflow now carries a deadline, and a dependency-free control keeps it that way.** Head `21b923dc2b7b8bc91f3829566739aa121037a6ca` — 3 files changed, +970 -0.

*The defect, in one sentence:* the `deploy` workflow carried no `timeout-minutes` on any of its 16 steps and no total deadline on its one job. **A step with no bound cannot fail — it can only hang**, until the runner's own six-hour limit, and the failure it produces names the JOB, never the step. That is exactly the remedy `opencharly/docs#162` names: *"a total deadline and a named step boundary, so a stall becomes a time-bounded failure that says where it died."*

**What this change is.** Three files, one idea:

- **`.github/scripts/check_step_timeouts.py`** (new, 718 lines) — the control. It reads this repo's workflow files with a dependency-free indentation reader (the repo carries no YAML parser: `package.json` holds astro, starlight, sharp and wrangler) and asserts that every job has a total deadline and every step has a step deadline **shorter** than its job's — a step bound at or above its job's is dead code, because the job's deadline fires first and the step never gets to name itself. It ships with a `--self-test` mode, and both are wired into `deploy.yml` as its first three steps: the check before the expensive work, then two proofs that the check can fail.
- **`.github/scripts/test_check_step_timeouts.py`** (new, 178 lines) — the mutation harness. It removes each of the checker's five mechanisms in turn and asserts that the self-test then turns RED on the fixture that covers exactly that mechanism; a mutant that still passes is a mechanism the self-test does not reach, and the harness fails on it. Each mutation is an asserted single-string replacement — the anchor must occur exactly once in the committed source, so a moved anchor fails loudly instead of masquerading as a passing mutation.
- **`.github/workflows/deploy.yml`** — the `deploy` job's total deadline (60 min) and a deadline on each of its 19 steps.

**The scope decision, and why the copy is not edited here.** One workflow file in this repo is not this repo's to fix: `.github/workflows/tag-on-merge.yml` is a **distributed copy** of opencharly/.github's canonical template (`.github/workflows/tag-on-merge-dispatcher.yml`), which that repo's bootstrap installs into every repo and whose reconcile script binds the copies back to it. A deadline added to the copy would duplicate the template's rule (R2) and would be **erased** by the org's own reconcile pass — a bound that the org's tooling can silently revert is not a bound. The copy is therefore restored to its pre-change content, and the checker **REPORTS** it — naming the owner and both tracking issues — instead of asserting it, because a skip that says nothing is a gap nobody can see. A path named explicitly on the command line is still asserted, so the copy's three unbounded surfaces — two jobs and one step — stay one command away (pasted in *How tested* below).

**The bounds are sized from the measured runs, not chosen.** The measurement window is FIXED and dated, because a sliding window moves under the numbers written next to it: over 2026-09-22..2026-10-24 (56 successful runs) the job's median is 10.62 min and its longest is 15.15 min, on 2026-09-22 — and that 15.15 min is also the longest of all 583 successful runs in the retained history, back to 2026-08-03. **The job's 60-minute total is 4.0x that maximum; the `Regenerate` step's 30-minute bound is 2.8x the 10.82 min that step has ever taken across the same 56 runs.** Real work does not trip either bound, and both fire long before the runner's own six-hour limit.

**The interlock with the org validator.** The `deploy` check is one of the checks the org validator's `arm` job waits for, and that job has been bounded since 2026-10-23 (`opencharly/.github#236`): the `arm` job at 75 minutes, its head-settle step at 70. This job's total is 60 — **under** the validator's wait — so a stall in this workflow now fails, and says WHICH step, before the validator gives up waiting for the head to settle. The deadlock's other half is therefore already landed; this PR is the docs-repo half of it.

**What this PR does NOT claim.** It does not claim to have reproduced the over-an-hour stall the issue describes. The runs that issue names have since completed, and each of them finished well inside an hour:

**And one honest limit of the mechanism, stated rather than papered over.** A job's `timeout-minutes` starts when the job STARTS RUNNING; it does not bound the time the job spends queued for a runner. This cross-check is an author-side verification and NOT a committed CI step: this repository carries no YAML dependency, and adding PyYAML to the workflow to prove a dependency-free checker would put the dependency back in. **The tool that produced the block is author-side and is not committed to this repository**, so its full source is pasted here — the reader can save it and re-run the command, and the file set is re-gatherable by the first line:

```
"""Cross-check the checker's FINDINGS against PyYAML's own reading of the same files.

The checker reads YAML with its own indentation reader (the repo carries no YAML
parser); PyYAML is an INDEPENDENT reading of the same bytes. The two must agree
on the IDENTITY of every finding (kind, job, step), not merely on the count.
"""
import importlib.util, pathlib, sys
import yaml

import os
spec = importlib.util.spec_from_file_location("chk", os.environ.get("CHK", ".github/scripts/check_step_timeouts.py"))
chk = importlib.util.module_from_spec(spec); spec.loader.exec_module(chk)

def yaml_ids(text):
    doc = yaml.safe_load(text); out = []
    for jname, job in (doc.get("jobs") or {}).items():
        if not isinstance(job, dict): continue
        jm = job.get("timeout-minutes")
        if not isinstance(jm, int): out.append(("job", jname, None))
        for i, s in enumerate(job.get("steps") or [], 1):
            if not isinstance(s, dict): continue
            sm = s.get("timeout-minutes")
            if not isinstance(sm, int): out.append(("step", jname, i)); continue
            if isinstance(jm, int) and sm >= jm: out.append(("dead", jname, i))
    return out

def mine_ids(text):
    out = []
    for m in chk.check_text(text, "f"):
        if "its deadline" in m and "is dead" in m: out.append(("dead", m))
        elif ": step " in m: out.append(("step", m))
        elif ": job " in m: out.append(("job", m))
    return out

def ident(kind, msg):
    parts = msg.split("'")
    job = msg.split("job '")[1].split("'")[0]
    if kind == "job": return ("job", job, None)
    step = int(msg.split("step ")[1].split(" ")[0])
    return (kind, job, step)

files = [pathlib.Path(p) for p in sys.argv[1:]]
mismatches = 0
for p in files:
    text = p.read_text()
    mine = sorted(ident(k, m) for k, m in mine_ids(text))
    theirs = sorted(yaml_ids(text))
    if mine != theirs:
        mismatches += 1
        print(f"MISMATCH {p}")
        print(f"   mine: {mine}")
        print(f"   yaml: {theirs}")
print(f"files compared: {len(files)}, mismatches: {mismatches}")
sys.exit(1 if mismatches else 0)
```
