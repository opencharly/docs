# 2026.230.9997 — escape the table pipe that made a correction invisible

<!-- PLACEHOLDER CalVer: the pr-validator regenerates this stamp at merge. -->

`docs#79` landed the `scp` → `ssh` correction in the `charly vm cp-box` quick-reference
row. The correction was right and **no reader could see it**.

The row wrote `` `podman save | ssh … podman load` `` with a RAW pipe, and backticks do
not protect pipes in GFM tables — the cell splits on the raw character regardless of code
spans. Against a 3-column header the row yielded 4 cells, so its third cell rendered as a
dangling `` `podman save `` and everything after the pipe was discarded as overflow:
`ssh`, "streamed", "no intermediate tarball", "verified-idempotent", all gone.

The row was already broken before that leg; the leg changed only HOW it was broken, from
two unescaped pipes to one. Fixing wording without fixing the pipe ships a cure nobody
can read.

The file already knew the answer two lines up — line 45 escapes the pipe in
`` `charly vm gpu mode [vfio\|nvidia]` ``. The page disagreed with itself within one
screen, which is the cheapest place to look before reasoning about the syntax.

Verified by RENDERING rather than by argument, through GitHub's `/markdown` endpoint in
`gfm` mode, with the correctly-escaped row two lines above as the control:

```
header cells: 3
data cells:   6        (2 rows x 3 — the control and the fixed row)
"no intermediate tarball" present in the rendered output
```

Before the fix the same check yielded 4 cells for this row and dropped the text.

A header-relative sweep found no other row in this table disagreeing with its own header.
The first sweep written for this was useless and worth recording as a method note: it
assumed every table was 3-column and flagged 38 correct rows in 2-column tables. Comparing
each row to ITS OWN table's header, splitting on unescaped pipes the way GFM does, is the
check that discriminates.

Fixed at the candy source (`candy/charly-vm/charly.yml`, `charly#315`) and regenerated —
never hand-edited here.
