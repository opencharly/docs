# 2026.227.0845 — regenerate the rpmfusion candy page

Regenerates `reference/candy/rpmfusion.md` from the superproject's
`candy/rpmfusion/charly.yml`, whose description and acceptance plan changed when
the RPM Fusion release packages became signature-verified.

## Why this is a separate landing

The generated page is a projection of a candy this site does not own. The
superproject change that alters it — importing the RPM Fusion keys from Fedora's
signed `distribution-gpg-keys` package so `localpkg_gpgcheck=1` can verify the
release rpms — is landing in its own cutover. Its `task docs:drift` gate fails
until this page is regenerated and committed here, so this repo lands first and
the superproject re-pins `DOCS_REF` to the result.

## What changed on the page

- the candy's description now states that the release packages are installed
  with their OpenPGP signatures **verified**, rather than merely installed;
- the plan gains a `rpmfusion-key-imported` check asserting an RPM Fusion key is
  present in the rpm database, and its install step is the three-command
  key-import-then-verified-install sequence.

No hand-authored page changed. No route moved.
