# 2026.231.0003 — escape the table pipe that made a correction invisible

`docs#79` landed the `scp` → `ssh` correction in the `charly vm cp-box` quick-reference
row. The correction was right and **no reader could see it**.

The row wrote `` `podman save | ssh … podman load` `` with a RAW pipe, and backticks do
not protect pipes in GFM tables — the cell splits on the raw character regardless of code
spans. Against a 3-column header the row SPLITS into 4 cells, GFM renders the first three
and DISCARDS the excess — so its third cell rendered as an unterminated code span and
everything after the pipe was thrown away: `ssh`, "streamed", "no intermediate tarball",
"verified-idempotent", all gone.

The row was already broken before that leg; the leg changed only HOW it was broken, from
two unescaped pipes to one. Fixing wording without fixing the pipe ships a cure nobody
can read.

The file already knew the answer two lines up — line 45 escapes the pipe in
`` `charly vm gpu mode [vfio\|nvidia]` ``. The page disagreed with itself within one
screen, which is the cheapest place to look before reasoning about the syntax.

Verified by RENDERING rather than by argument, through GitHub's `/markdown` endpoint in
`gfm` mode, with the correctly-escaped row two lines above as the control:

```
                        BEFORE (raw |)   AFTER (\|)
rendered <th> cells           3              3      <- identical: proves nothing
rendered <td> cells           6              6      <- identical: proves nothing
"no intermediate tarball"     0              1      <- DISCRIMINATES
"verified-idempotent"         0              1      <- DISCRIMINATES
third cell                unterminated   <code class="notranslate">…</code>
```

**The cell counts do not discriminate, and an earlier draft of this entry cited them as
the proof.** Because GFM discards cells past the header width, a 4-way split still RENDERS
as three `<td>`s — before and after are byte-identical on that measurement. The figure "4
cells" is the MARKDOWN SPLIT, not what rendering returns; attributing it to a rendering
check was wrong in a document whose thesis is verify-by-rendering.

The evidence that actually separates the two states is the presence of the text, which is
also the thing a reader loses. Recorded because an assertion that cannot fail on the
broken input is worse than no assertion: it reads as proof.

A header-relative sweep found no other row in this table disagreeing with its own header.
The first sweep written for this was useless and worth recording as a method note: it
assumed every table was 3-column and flagged 38 correct rows in 2-column tables. Comparing
each row to ITS OWN table's header, splitting on unescaped pipes the way GFM does, is the
check that discriminates.

Fixed at the candy source (`candy/charly-vm/charly.yml`, `charly#315`) and regenerated —
never hand-edited here.

**Reproducibility is qualified, and the qualification is load-bearing.** `charly#315` and
`plugins#208` are both OPEN, so this page reproduces from those branches and NOT from
landed state. Regenerating from `charly@main` + `plugins@main` today reverts it to
`podman save | scp | podman load … (idempotent)`, discarding this escape AND `docs#79`'s
`scp` → `ssh` correction. The window is bounded at the gitlink, as `docs#79` shipped under,
and closes when both land. `docs#79`'s own body already published this exact reversion at
the pin — so this is a carry-forward that should not have needed rediscovering.
