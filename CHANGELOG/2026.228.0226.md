# 2026.228.0226 — the published bootstrap excerpts match what the emitter emits

Regenerated from the superproject candy sources. `opencharly/sdk#138` (merged
`91cc241d`, tag `v0.2026228.209`) shipped **four** fixes, and these pages
described the pre-fix behaviour for two of them.

## What was false

**The cloud-init sshd start (fix 4)** — the runcmd was described as carrying
`systemctl unmask` + `enable --now` on every distro. On Alpine it carries
`rc-update add sshd default && rc-service sshd start`; there is no ssh.socket
and no systemctl.

**The create-mode bootstrap block (fixes 2 and 3)** — four pages printed the
emitted Containerfile verbatim as `groupadd` + `useradd -m … -s /bin/bash`, each
introduced as what the generator emits. It now probes:
`LOGIN_SHELL=/bin/sh; [ -x /bin/bash ] && LOGIN_SHELL=/bin/bash`, then
`command -v useradd` with a busybox `addgroup`/`adduser` fallback.

These are the published pages, so a stale excerpt is a reader copying a command
the product no longer produces.

Fix 1 (go-task `curl` → `(curl || wget)`) was already clean: every page elides
that line.

## Why the first sweep missed them

It keyed on the STRING it had just fixed rather than the CLAIM that became
false. Grepping `unmask`/`enable` finds the sshd sites and cannot see a stale
`useradd` block expressing a different falsified claim from the same commit.

Compounding it, the first pass never crossed a gitlink: `git grep` from a
superproject root does not descend into submodules, so this repo — the
highest-visibility surface — was invisible to it.

- old shape `useradd -m -u … -s /bin/bash` under `src/content/docs` — **6 hits before, 0 after**

- `task docs:sync` run with the `box/*` submodules INITIALIZED touched 6 files

  because absent sources read as pages to remove — the count is the control that
