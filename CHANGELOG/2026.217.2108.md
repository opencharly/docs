# 2026.217.2108 — the nesting excerpt is the verbatim entry

`scripts/verify-doc-excerpts.py` — the excerpt checker landing in the charly superproject —
asserts every fenced YAML block in the hand-authored pages is a verbatim excerpt of a committed
source. It was red on this tree in one place: the nesting illustration on
[`concepts/00-vocabulary.md`](/concepts/00-vocabulary/) showed `check-group-vm` indented **under**
`group:` and annotated the excerpt lines with inline comments — neither of which exists in the
real `check-group` entry in the superproject's `charly.yml`, where `check-group-vm` is a **sibling
member** of `group:` and the member `check-group-member` is nested under the VM node.

The block is now the canonical verbatim form already used by `concepts/02-one-recipe-many-molds.md`
and the quickstart — same tree position, `...` for the elided `description:` — and every remaining
line matches the source byte for byte.

The superproject's `README.md` carried the same two divergent blocks; the README fix and the
excerpt checker land in charly#221, and `index.md` — the generator-owned projection of the README
— regenerates in the follow-on docs sync that runs once that merges. This PR deliberately does not
carry the regeneration: at this PR's base, the README still has the old blocks, so a regenerated
`index.md` could not be reproduced by the committed inputs.
