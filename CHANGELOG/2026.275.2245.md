`start/`, `concepts/` and `guides/` are the teaching narrative the generator **never writes**. It does **read** them: the whole-site link gate runs over hand-authored pages exactly as over generated ones, so a dead site-absolute link here fails the docs build. That is why every link below is proven resolvable against the emitted tree rather than eyeballed, and why the pages link only to routes that exist.

**Two steps this plan expected turned out to be unnecessary, and I confirmed rather than assumed:**

- **No sidebar config change.** The Starlight sidebar is **autogenerated from the content tree** (`astro.config.mjs:26-28`, `{ label: 'Guides', items: [{ autogenerate: { directory: 'guides' } }] }`), so a new page under `guides/` appears in it by itself. Adding an explicit entry would have been redundant configuration.
- **No `kubernetes` command page is linked, because none exists.** `kubernetes`, `kube` and `kindcluster` are not among the 79 `reference/cli/` pages. `kubernetes:` is a deploy TARGET (a YAML key), not a verb. The page says so in its opening line and links `/reference/cli/deploy/` instead.

**One guide held back deliberately.** A fourth, `guides/containers-and-nesting.md`, is not in this PR: it would make nesting claims, and the loader's nesting semantics are under an open issue (opencharly/charly#748 — a member authored *beside* the kind key is classified deploy-level "alongside", while every bed's own description says it lands *inside* the guest). This PR does not publish a nesting claim the loader does not implement, and it leaves the three pages that make such claims (`start/quickstart.md`, `concepts/02-one-recipe-many-molds.md`, `concepts/12-boxes-all-the-way-down.md`) untouched.

Relates to **opencharly/charly#747** — the parent tracking issue for this docs/README truth sweep. This PR takes the "new hand-written guides" item for `vms`, `kubernetes` and `agents`; `containers-and-nesting` stays on that issue while #748 is open.

## Divergences found while verifying (reported, NOT fixed here — different repos)

Two document-vs-reality divergences surfaced during fact-checking; both are on the parent tracking issue and neither is in this repo:

1. **`spec/schema/vm.cue` says "5-arm" / "5-way discriminated union" while the block declares SEVEN `kind:` arms** (the grep above). The guide states the seven kinds and does not repeat the stale comment. The spec comment is its own fix.
2. **The generated recipe `recipes/kubernetes/kubernetes.md` documents the kubernetes deploy as `charly fleet add/sync/del`, but no `fleet` command word exists** — `plugin-fleet` declares `command:deploy`. That page projects from a skill source that still spells the retired `fleet` verb, so the fix belongs in that skill's owning repo followed by a marketplace regeneration. This PR's kubernetes guide uses the real verb and does not repeat the stale spelling.
