# 2026.240.0712 — fix: remove the charly submodule; clone charly recursively at CI time

## Summary

The candy de-submodule scaffold copied the umbrella structure into every standalone repo, declaring a `charly` git submodule (`path = charly`, `url = https://github.com/opencharly/charly.git`, `branch = main`). The refs downloader's `populateSubmodules` (spec/refs/git.go) initializes EVERY declared submodule on fetch — so a consumer fetching this candy at any ref pulls the ENTIRE opencharly/charly repo into `charly/` inside the fetched tree. That leaked tree breaks the charly parity test (TestFleetCompileParity_PluginRoundTrip): its seedParityProject copies the fetched fixture into .parity/candy/<name>, the .parity root's `discover: candy recursive` walks into .parity/candy/<name>/charly/ finding the ROOT's charly.yml (agentteams box + 663 candy manifests), so cfg.AllBoxNames() returns the root's boxes and the compile resolves "agentteams" instead of the 3 parity fixtures.

**Fix:** remove the submodule gitlink + `.gitmodules`, and make the CI-time charly clone reproduce the exact committed content tree:

1. **Pin the CI-time clone at `5716706651`** — the SAME commit the removed submodule recorded. LIVE-PROVEN root cause: the previous PR pinned `v2026.238.1242` (post-cutover), whose checkout has only 14 candy dirs — `candy/plugin-docs` moved to a standalone repo, so `charly docs generate` failed with `unexpected argument docs` (exit 80), and the committed content's links to in-repo candy pages (sshd, fleet, plugin-example) resolve to nothing at that tag. At `5716706651` (pre-cutover), `candy/plugin-docs` is still in-repo and the committed content tree was generated against exactly this checkout.
2. **Fix the submodule init order**: `git clone --recursive` pulls each box/* at its default-branch HEAD, but the committed content was generated against the box commits `charly@5716706651` records. The shipped step now clones WITHOUT `--recursive`, checks out the pinned commit, THEN runs `git submodule update --init --recursive` — pinning the box submodules to the exact commits the committed content was generated against.
