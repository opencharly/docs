docs: retire the fleet CLI page (bump plugin-docs + plugin-fleet pins, regenerate)

## Summary

Retires the last `fleet` surface on the live site by moving two pins and regenerating.

- **`plugin-docs` deploy pin → `v2026.256.1653`** — carries charly/plugin-docs#8 (total-order sort
  keys), so a corpus pin change no longer reshuffles the census.
- **corpus `plugin-fleet` pin → `v2026.250.0829`** (the version charly compiles). The stale
  `v2026.242.1727` declared `command:fleet`, which is why the retired word persisted.
- **Regenerated**: `fleet` is gone from `reference/providers.md`; `reference/cli/fleet.md` is deleted;
  `reference/cli/deploy.md` has a single owner again; `plugin-fleet` is documented once (compiled),
  and the `plugin-docs` page advances to `v2026.256.1653`.

**Why pin to the compiled version.** Pinning plugin-fleet to a *different* deploy-declaring tag
(e.g. `v250.0537`) documents the same candy twice, and `generateCLI` then renders its one command
word with **two identical `plugin-fleet` owners** (a duplicated "About plugin-fleet" block and a
misleading "served by 2 plugin candies"). Pinning to the version charly compiles collapses the two
entries to one — the duplicate owner disappears and the candy's `deploy` placement stays correct.
