# 2026.227.1224 — docs: codify the docs-projection coupling and the --remote reconcile hazard

## Summary of changes

Codifies two proven operational facts that lived only in a session transcript. The skills doctrine is explicit that a proven, generalizable insight left uncommitted is a knowledge leak — every contributor and every fresh validator re-derives it.

**Lesson 1 — editing a source is a docs landing.** `reference/` and `recipes/` are PROJECTIONS of files people edit for reasons unrelated to the site. Any such edit re-projects its page and `task docs:drift` fails until the regenerated page is committed in `docs`. **A one-line prose fix is never a one-repo change.**

The two chains are not the same length, and that distinction is the useful part:

- **Candy/box prose — ONE hop.** `reference/candy/` and `reference/box/` are read straight off disk. Editing a `description:` or `plan:` re-projects the page in the same tree, immediately; the `docs` commit belongs to the same cutover.
- **Skill prose — TWO hops.** `recipes/` is NOT read from `candy/*/charly.yml`. A `skill:` entity is projected by `charly marketplace generate` into `plugins/**/SKILL.md`, and `charly docs generate` reads **that projection**. So a skill edit reaches readers only once the `plugins` landing merges and the gitlink advances — and **advancing that gitlink without regenerating `docs` in the same change is what leaves the site stale**, with nothing but `task docs:drift` to say so.

**Lesson 2 — `charly box reconcile --remote` is not idempotent against a moving remote.** It re-resolves the *newest* tag each invocation, so re-running after a sibling repo publishes silently re-bumps every pin. Use the plain form to *check*.
