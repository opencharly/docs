# 2026.216.2142 — docs(landing): a front page with a spine, and /grievances/ on the site

## Summary of changes

The operator's finding, verbatim: *"your whole readme and OpenCharly.ai intro is one confusing
mess overall … both the vision and grievances is something for the docs. the intro should be a 60
second intro to what Charly is, how it's working and what it's explaining it's core capabilities."*

This is the docs half. Three commits.

### 1. The reader claims are gone

The page opened by telling the reader how they would feel — *"that part will feel familiar"*, *"the
part that usually does not"* — and then, before saying what charly is, showed a table of *"you
already use X, charly's equivalent is Y"* plus the assertion *"most toolchains leave that line
empty"*.

None of that is checkable against anything, and this project's standard is that nothing ships in
the docs that cannot be verified. A reader who does not run Packer or Ansible also learned nothing
from a comparison to them. Deleted, not softened.

### 2. The page has a spine

Before: what it is → a roles table → four commands → four cards restating the vision → a link list.
A reader looking for *how does this actually work* had to assemble it from three non-adjacent
sections.

After — three sections in reader order:

| Section | Contains |
|---|---|
| **What it is** | two paragraphs, no headings, no tables |
| **How it works** | three subsections: the words · one keyword, three roles · the four stages |
| **A real box, end to end** | the four commands, what the box does *not* declare and why, the substrate swap |

Then *where to go next*.

### 3. The vision left the front page, and the grievances arrived on the site

The four **"The bet"** cards restated tenets 1, 2, 4 and 6 of `VISION.md`. That is the thesis, not
the mechanics, and the front page is not where a reader meets the thesis — it now links to
`/vision/` instead of paraphrasing a quarter of it. The freed card grid carries the four stages,
which is what a reader at that point is trying to learn.

The **hero tagline** claimed *"Every other tool hands an agent a sandbox and then spends its effort
taking things away."* Nothing verifies an assertion about every other tool. Replaced with the
project tagline, which describes charly.

**`/grievances/` is new.** `GRIEVANCES.md` was reachable only as a file in the charly repository;
it is now generated into this site the same way `/vision/` is, and sits in the sidebar beside it.
The generator side is the companion charly PR — this PR carries the generated page and the sidebar
entry.

## Change class

**Documentation-only.** Hand-authored `index.mdx`, one generated page, one CHANGELOG entry, and
one line of `astro.config.mjs`. No Go, no schema, no candy body.

**On that config line, since "documentation-only" selects the lighter gate and should not be
claimed loosely:** `astro.config.mjs` is configuration, not markdown. The line adds one sidebar
entry — `{ label: 'What it is reacting to', link: '/grievances/' }` — to a static array. It is
navigation data for the site being documented, it changes no product behaviour, and this
repository's only runtime surface is the site build, which is green at exit 0 on every revision of
this branch. An earlier version of this section said "no config", which was wrong; the honest
statement is that there is one config line and here is why it does not change the class.

**Correction to an earlier version of this description.** It called the `docs:drift` no-op the
load-bearing proof that `grievances.md` is a projection rather than a hand-written copy. That claim
was too strong, and measuring it is what showed why.

What drift genuinely proves: the generator rewrites `grievances.md` on every run, so if the
committed content differed from the generator's output by so much as a byte, drift would fail.
Content-equality is real.

What it did NOT prove: that the page is generated **at all**. The generator only ever wrote pages
and never removed them, so a page it stopped emitting stayed in the tree and drift saw no
difference. Measured, not theorised — removing the `generateGrievances` call and re-running
`task docs:sync` reported *"already up to date (regeneration is a no-op)"* and exit 0 while the
generator no longer produced the page at all.

The companion charly PR closes that hole: the generator now clears every page carrying the
`DO-NOT-EDIT` header before emitting, so a page it no longer produces does not come back. With that
in place the same negative test fails loudly, which is the coverage this page actually rests on:

```
$ # generateGrievances call removed, then:
$ task docs:sync
charly docs: 1 internal link target(s) resolve to no page:
  /grievances/
    linked from: index.mdx
every internal link must resolve to a page the site emits
EXIT=1
```

Restoring the call returns the tree to clean with no manual repair. The prune is non-destructive to
hand-authored pages by construction — it matches on the generated header, never on a path — and the
control run demonstrates it: 831 pages cleared and re-emitted, `git status` empty afterwards, with
`index.mdx`, `start/`, `concepts/` and `guides/` untouched.

The projection was also read rather than assumed: the source H1 is dropped (Starlight renders the
frontmatter title, so keeping it would show the heading twice), and both repo-relative links were
rewritten — `](VISION.md)` → `](/vision/)` and `](plugins/README.md)` → `](/recipes/)`. Zero
repo-relative targets survive in the generated page.
