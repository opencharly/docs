# 2026.227.0855 — regenerate the rpmfusion candy page (description correction)

Regenerates `reference/candy/rpmfusion.md` after a false claim was corrected in
the superproject's `candy/rpmfusion/charly.yml` description.

## What was wrong

The description stated that each RPM Fusion release package "imports the signing
keys". It does not. It drops the repo signing-key FILES under
`/etc/pki/rpm-gpg/` and wires `gpgkey=file://…` into the `.repo`; nothing reaches
the rpm database until something imports it.

Measured two independent ways in the superproject cutover: a throwaway
`fedora:43` container running the old install flow reports **zero** rpmfusion
keys from `rpm -q gpg-pubkey`, and the published `fedora-nonfree:2026.216.1908`
image carries **0** while a freshly built one carries **2**.

## Why a third landing for one candy

The previous landing (`v2026.227.0844`) projected a description that still
contained the false sentence — it was introduced as a contradiction in the same
edit that added the corrected wording two lines above it. Correcting the source
re-projects the page, and the page is a projection this repo does not own.

Publishing a known-false claim because the page had already merged is not a
trade this project makes, so the page is regenerated rather than left standing.

No hand-authored page changed. No route moved.
