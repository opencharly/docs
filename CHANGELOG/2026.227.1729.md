## Why a wholesale regeneration is NOT run before merging

`charly docs generate` rewrites the generated trees wholesale, so regenerating
from a `plugins` checkout OLDER than one a page was already projected from
DELETES that page's newer content — silently, as ordinary generator output that
reads like the author's own diff.

That is not hypothetical here. This branch went `BEHIND` when the previous docs
leg merged, and after the `gh pr update-branch` recovery a regeneration at
`4458a400` removed 59 lines from `recipes/check/check/beds-and-r10.md` — a
section projected from a LATER `plugins` commit that this checkout does not
contain. The deletion was never staged. The page in this commit is the merged
base's version, inherited untouched.

The mirror is mid-chain by construction while several legs land in a forced
order, so **no `plugins` checkout yields a clean `docs:drift` right now**, and the
verdict's colour is a fact about the checkout rather than about this branch:

| `plugins` checkout | what regeneration would change | whose work |
|---|---|---|
| `4458a400` (this leg's pin) | deletes 59 lines from `recipes/check/check/beds-and-r10.md` | the previous docs leg's — must NOT be committed |
| the `plugins` tip | adds `recipes/internals/git-workflow/evidence-and-freshness.md` changes | another leg's pending mirror |

Read a drift verdict together with the pointer it was measured at, or it is not a
statement about anything. The check this leg can answer is the one at the tip:
