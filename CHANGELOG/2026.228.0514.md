## What the corrected prose says

`keep_images: N` keeps the newest N distinct images per box **and at most N tags of each**, where
a *distinct image* is a distinct image ID. It also now states **which verb reclaims what**: the
post-build pass cannot remove an image's last tag, so it never reclaims a distinct image — only
surplus tags of images wearing several. The distinct-image budget is enforced by `charly clean`,
and a project that only ever builds accumulates distinct images past `keep_images` with no
surface reporting it.
