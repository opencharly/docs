# 2026.215.1850 — the gourmet-kitchen landing, and a twelve-part concepts curriculum

The site had five concept pages in no particular order, a landing page that repeated the README's
lifecycle table, and a quickstart that opened by building a file the reader had never seen. This
rebuilds the hand-authored half around one audience — someone who already runs containers and VMs —
and one teaching order.

## The curriculum

`concepts/` becomes a glossary plus twelve pages, one per [vision](/vision/) tenet, in the vision's
own order. Every page uses the same skeleton, and the sameness *is* the pedagogy:

> the tenet, quoted · **The idea** (theory, no commands) · **In practice** (runnable, excerpted
> from a real committed candy) · **If you know …** (the delta from Docker / libvirt / Ansible /
> integration testing) · **See also** (links only, never a second explanation)

| Page | Tenet |
|---|---|
| `00-vocabulary` | — the words, defined once |
| `01-the-box-is-the-boundary` … `12-boxes-all-the-way-down` | tenets 1–12, in order |

Replaces `candies-and-boxes`, `candyboxing`, `lifecycle`, `rdd-and-ade`, `schema-and-versions`.

## The two things that were actually broken

**"box" and "candybox" were used interchangeably and never distinguished.** They are not the same:
a box is an image sitting in storage; a candybox is that image *running* somewhere isolated, and it
is the candybox's walls the security model talks about. `concepts/00-vocabulary` is now the single
canonical definition, and every other page links to it rather than redefining.

**Nothing showed a reader a `charly.yml` and then the commands that act on it.** The quickstart
opened with `charly box build fedora` — a build of a file the reader had never seen. It is now
config-first: read `tutorial-shell`, then build it, enter it, prove it.

## Every example is a real, tested candy

The rule is **excerpt, never invent**: a fenced YAML block is *either* a verbatim excerpt of a
committed file, *or* a template the prose explicitly frames as one for the reader's own project.
Every block is **either** a verified excerpt **or** a declared template — the checker's
`unclassified` count must be 0, and that is the assertion worth making. Block and line counts move
with every edit, so they are deliberately not stated here: an immutable entry cannot carry a
figure that changes.

| Role | Artifact |
|---|---|
| layer | `candy/ripgrep/charly.yml` |
| box | `box/fedora/box/tutorial-shell/charly.yml` (new, with a `disposable: true` bed) |
| bed | `box/fedora/charly.yml` (`check-tutorial-shell`) |
| plugin | `candy/plugin-example/charly.yml` |

The superproject's `scripts/verify-doc-excerpts.py` enforces it (it reads sources from three repos, so only a superproject checkout can run it), and it is written to **fail on any block it cannot
classify** rather than skip it. That shape was earned: the first version keyed blocks by name and
silently skipped anything unrecognised — 9 of 15 blocks — while reporting a confident pass. One of
the blocks it skipped quoted a `plan:` that had never existed in any committed revision. A checker
that skips what it does not recognise reports success on what it never checked.

This mattered more than it looks. The repository's own `charly.yml` entries are architectural R10
fixtures — accurate, and unreadable as teaching material. Rather than paraphrase them into
plausible YAML nobody executes, `tutorial-shell` was added upstream as a real box with a bed in the
acceptance roster.

## The fabricated quote, and what it cost to find

`concepts/05` introduced a YAML block with *"quoted from `box/fedora/charly.yml`"* and then showed a
`plan:` that **does not exist in that file and never has** in any committed revision. The real
`check-tutorial-shell` carries no `plan:` at all.

It arrived by a mechanism worth naming. The block was a faithful excerpt when written — of the bed's
*original* shape, before an R3 correction upstream deleted that plan as a duplicate of `sshd`'s own
probe. The correction was propagated to `concepts/02` and the quickstart and **missed this page**;
then a later mechanical rename swept `tutorial-shell-dev` → `check-tutorial-shell` *inside* the
stale block, which made it look current while its content described a deleted design. A stale
excerpt that gets cosmetically refreshed is harder to spot than one that goes obviously out of date.

Two things made it worse than a typo. It falsified this change's own headline claim — that every
block is a verified excerpt — on the page that teaches *"when a bed contradicts a document, the
document is wrong"*. And the invented step was a bed-level duplicate of a candy probe: the exact
anti-pattern the upstream correction existed to remove, so the site briefly taught both the rule
and its violation.

The page now quotes the bed as it really is — four lines, no `plan:` — and teaches the better
lesson that was there all along: what a bed proves is the *sequence* (build, deploy, steady state,
destroy, rebuild, re-prove), not a step someone authored on it.
